❯ what A B and C?                                                               

● These are the three ways to handle sampling now that temperature is gone.

  The problem: Agentless takes several samples per stage: the first at
  temperature 0, the rest at 0.8. The 0.8 samples are meant to give different
  localizations and patches to choose from. All the current models ignore or
  reject temperature, and Phase 0 made the code stop sending it. So the extra
  samples may come back nearly identical, which means you pay for them without
  getting any variety.

  The options:

  - A. Change the prompt for each sample. Give each sample after the first a
    slightly different prompt. For example, shuffle the order of the files or
    edit locations, or add a short instruction like "propose a different
    approach from the obvious one." Then remove duplicate answers.
    - Pros: works the same way for DeepSeek, OpenAI and Anthropic, so
      comparisons between providers stay fair.
    - Cons: the prompts no longer match the original Agentless exactly, and the
      write-up has to say so.
  - B. Use each provider's own randomness controls. Rely on whatever each API
    still offers: a seed, reasoning-effort settings, or just the randomness the
    models already have.
    - Pros: prompts stay the same as the original.
    - Cons: each provider needs its own code, there's no guarantee the samples
      will differ, and each provider would get variety in a different way.
  - C. Accept less variety. Take fewer samples, maybe just one, and rely on the
    newer models being stronger.
    - Pros: the cheapest and simplest option, with no extra code.
    - Cons: drops the multi-sample and reranking part of Agentless, which is a
      weaker basis for comparing with the paper's results.

  My recommendation is A. It's the only option that behaves the same across all
  three providers. That matters if your FYP compares providers.
